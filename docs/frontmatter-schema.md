# Digital Garden - Frontmatter Field Reference

**Version:** 1.0
**Date:** 2025-11-13

Complete reference for all frontmatter fields used in the Digital Garden system.

---

## Quick Reference

```yaml
---
# Core Hugo (Required)
title: "Article Title"
date: 2024-11-13
lastmod: 2024-12-05
draft: false

# Digital Garden (Required)
growth_stage: seedling
last_significant_update: 2024-12-05

# Digital Garden (Optional)
weight: 1
history:
  - date: 2024-12-05
    note: "Description"
    stage: seedling  # optional

# Standard Fields (Existing)
description: "SEO description"
tags: ["tag1", "tag2"]
categories: ["Category"]
authors: ["angel"]
---
```

## Core Hugo Fields

### `title`

**Type:** String
**Required:** Yes
**Example:** `"Complete Guide to Hugo"`

**Description:** Article title displayed in headers, cards, and metadata.

**Rules:**
- Must be unique across site
- Keep under 60 characters for SEO
- Avoid special characters in URLs

---

### `date`

**Type:** Date (ISO 8601)
**Required:** Yes (auto-generated by Hugo)
**Example:** `2024-11-13`

**Description:** Original creation date. **NEVER changes** after creation.

**Purpose:**
- Used for "New" badge logic (< 4 weeks old)
- Original planting timestamp
- Archive organization

**Hugo behavior:**
```bash
hugo new content/articles/my-article/index.md
# Creates with date: 2024-11-13T10:30:00+01:00
```

**Manual format:**
```yaml
date: 2024-11-13              # Preferred: YYYY-MM-DD
date: 2024-11-13T10:30:00Z    # With time
```

---

### `lastmod`

**Type:** Date (ISO 8601)
**Required:** No (auto-updated by Hugo)
**Example:** `2024-12-05`

**Description:** Last file modification date. **Automatically updated** on every save.

**Purpose:**
- "Last edited" display
- NOT used for grace period (use `last_significant_update`)
- RSS feed ordering

**Hugo auto-update config:**
```toml
# config.toml
[frontmatter]
  lastmod = [":git", "lastmod", ":fileModTime", "date"]
```

**Manual override:**
```yaml
lastmod: 2024-12-05  # Hugo respects manual value
```

---

### `draft`

**Type:** Boolean
**Required:** No
**Default:** `false`
**Example:** `draft: true`

**Description:** Hide article from builds.

**Behavior:**
- `draft: true` → Only visible with `hugo server -D`
- `draft: false` or omitted → Published

## Digital Garden Fields

### `growth_stage`

**Type:** String (enum)
**Required:** Yes
**Default:** `seedling`
**Values:** `seedling`, `budding`, `evergreen`, `withered`

**Description:** Current maturity level of content.

**Values:**

| Value | Icon | Meaning | When to Use |
|-------|------|---------|-------------|
| `seedling` | 🌱 | Early exploration | First draft, rough ideas |
| `budding` | 🌿 | Refined, evolving | Clarified, but not finished |
| `evergreen` | 🌳 | Mature, reliable | Polished, comprehensive |
| `withered` | 💀 | Deprecated | Outdated, archived |

**Examples:**
```yaml
# New article
growth_stage: seedling

# After revision
growth_stage: budding

# Fully refined
growth_stage: evergreen

# Deprecated
growth_stage: withered
```

**Important:**
- Change manually (not automatic)
- Add history entry when changing
- Withered articles hidden from default view

---

### `last_significant_update`

**Type:** Date (ISO 8601)
**Required:** No (defaults to `date`)
**Example:** `2024-12-05`

**Description:** Date of last **significant** content change. **Manually updated**.

**Purpose:**
- **Triggers grace period** (4 weeks from this date)
- Used in sorting algorithm
- Controls "New"/"Updated" badge display

**When to update:**
- Major content revisions
- New sections added
- Growth stage transitions
- Substantial rewrites

**When NOT to update:**
- Typo fixes
- Grammar corrections
- Minor formatting changes
- Link updates

**Example workflow:**
```yaml
# Small edit (typo):
# - Don't touch this field
# - Don't add history entry
# - lastmod auto-updates
# - No grace period reset

# Significant update:
last_significant_update: 2024-12-05  # Update manually
history:
  - date: 2024-12-05                 # Add matching entry
    note: "Rewrote intro section"
# - lastmod also auto-updates
# - Grace period resets to 4 weeks
```

**Default behavior:**
```go-html-template
{{- $sigUpdate := default .Date .Params.last_significant_update -}}
{{/* If not set, uses original date */}}
```

---

### `weight`

**Type:** Integer (1-10)
**Required:** No
**Default:** `1`
**Example:** `weight: 5`

**Description:** Manual priority/quality score. **Set once on publish, never changed.**

**Values:**

| Weight | Meaning | Effect |
|--------|---------|--------|
| `10` | Pinned | Appears in Tier 1 (top 3) |
| `5-9` | Important | +10-18 points to popularity |
| `1-4` | Normal | +2-8 points to popularity |

**Popularity score contribution:**
```
popularity_score = (hearts × 1) + (comments × 3) + (weight × 2)
```

**Pinning:**
```yaml
# Pin article
weight: 10

# Unpin (move to normal sorting)
weight: 5  # or any value 1-9
```

**Overflow handling:**
- If >3 articles have `weight: 10`
- Display top 3 by `lastmod DESC`
- Fourth falls to normal sorting

**Best practices:**
- Set on initial publish based on intuition
- Don't change later (let community decide quality)
- Reserve 10 for max 3 "start here" articles

---

### `history`

**Type:** Array of objects
**Required:** No (recommended)
**Example:** See below

**Description:** Timeline of significant changes to the article.

**Structure:**
```yaml
history:
  - date: 2024-12-05
    note: "Refined introduction section"
    stage: budding  # optional

  - date: 2024-11-13
    note: "Initial planting"
    stage: seedling
```

**Field details:**

#### `history[].date`

**Type:** Date (ISO 8601)
**Required:** Yes
**Format:** `YYYY-MM-DD`

**Rules:**
- Must be valid date
- Should match `last_significant_update` for latest entry
- Chronological order (newest first recommended)

#### `history[].note`

**Type:** String (Markdown allowed)
**Required:** Yes
**Max length:** ~200 characters (for UI display)

**Content guidelines:**
- **Do:** Describe WHAT changed and WHY
- **Do:** Use reader-friendly language
- **Don't:** Technical git-style messages
- **Don't:** Granular line-by-line changes

**Good examples:**
```yaml
note: "Rewrote intro section for clarity"
note: "Added new section on performance optimization"
note: "Promoted to evergreen after community validation"
note: "Deprecated - see [new approach](/new-article)"
```

**Bad examples:**
```yaml
note: "Fixed typo in line 42"           # Too granular
note: "Updated code block syntax"       # Too technical
note: "Merged PR #123"                  # Not user-facing
```

#### `history[].stage`

**Type:** String (enum)
**Required:** No (include when stage changes)
**Values:** `seedling`, `budding`, `evergreen`, `withered`

**When to include:**
- Growth stage transitions only
- Omit for regular content updates

**Example:**
```yaml
history:
  - date: 2024-12-03
    note: "Promoted to evergreen"
    stage: evergreen  # Include

  - date: 2024-11-05
    note: "Added new section"
    # No stage field (no transition)
```

**Display behavior:**
- Entries with `stage` show icon (🌱🌿🌳💀)
- Entries without `stage` show default icon (📝)

---

### `history` Best Practices

**Frequency:**
- Add entry for each significant update
- Not required for minor edits
- Include stage transitions

**Ordering:**
- Newest first (recommended for sidebar display)
- Or oldest first (if showing full timeline)

**Consistency check:**
```yaml
# Latest history date should match last_significant_update
last_significant_update: 2024-12-05

history:
  - date: 2024-12-05  # ✅ Matches
    note: "..."
```

**Validation:** Hugo warns if mismatch detected.

## Standard Fields (Existing)

These fields continue to work as before. No changes needed.

### `description`

**Type:** String
**Required:** Recommended
**Example:** `"Learn how to build static sites with Hugo"`

**Purpose:**
- SEO meta description
- Social media previews
- Article card summaries

---

### `tags`

**Type:** Array of strings
**Required:** No
**Example:** `["hugo", "webdev", "tutorial"]`

**Purpose:**
- Content taxonomy
- Tag archive pages
- Related articles

**Type:** Array of strings
**Required:** No

**Purpose:**
- Content organization

- Primary topic classification

**Type:** Array of strings
**Required:** No

**Purpose:**
- Link related articles

## Archetype Template

New articles created with `hugo new` use this template:

`archetypes/articles/index.md`:

```yaml
---
title: "{{ replace .File.ContentBaseName "-" " " | title }}"
date: {{ .Date }}
lastmod: {{ .Date }}
draft: true

# Digital Garden
growth_stage: seedling
weight: 1
last_significant_update: {{ .Date }}

history:
  - date: {{ .Date | time.Format "2006-01-02" }}
    note: "Initial planting"
    stage: seedling

# Standard fields
description: ""
tags: []
categories: []
authors: ["angel"]
---

Your content here...
```

**Usage:**
```bash
hugo new content/articles/my-new-article/index.md
```

## Validation Rules

### Build-Time Checks

Hugo will warn or error on:

**Errors (build fails):**
- Missing `title`
- Missing `date`
- Invalid `growth_stage` value
- Invalid `weight` value (not 1-10)

**Warnings (build succeeds):**
- `last_significant_update` doesn't match latest history
- Future date in `last_significant_update`
- Missing `note` in history entry
- >3 articles with `weight: 10`

### Manual Validation Checklist

Before publishing:

- [ ] `title` is descriptive and unique
- [ ] `growth_stage` matches content maturity
- [ ] `weight` set appropriately (1-10)
- [ ] `last_significant_update` matches latest history
- [ ] `history` entries have dates and notes
- [ ] `description` written for SEO
- [ ] `tags` and `categories` assigned
- [ ] `draft: false` to publish

## Migration Guide

### Existing Articles → Digital Garden

**Step 1:** Add required fields
```yaml
growth_stage: budding  # Choose appropriate stage
last_significant_update: 2024-11-13  # Use lastmod or date
```

**Step 2:** Add initial history
```yaml
history:
  - date: 2024-11-13  # Use current date
    note: "Migrated to digital garden"
```

**Step 3:** Set weight (optional)
```yaml
weight: 1  # Default, or higher for important articles
```

**Step 4:** Review and refine
- Is `growth_stage` accurate?
- Should this be pinned (`weight: 10`)?
- Add more history if available?

## Troubleshooting

### Common Mistakes

**Problem:** Grace period not resetting after update

**Cause:** Forgot to update `last_significant_update`

**Fix:**
```yaml
# Update this field manually:
last_significant_update: 2024-12-05

# And add history entry:
history:
  - date: 2024-12-05
    note: "Description of change"
```

---

**Problem:** Article not showing in homepage

**Cause:** `growth_stage: withered` (hidden by default)

**Fix:**
```yaml
# Change to appropriate stage:
growth_stage: budding
```

---

**Problem:** History dates don't match warning

**Cause:** Mismatch between `last_significant_update` and latest history entry

**Fix:**
```yaml
# Keep these in sync:
last_significant_update: 2024-12-05

history:
  - date: 2024-12-05  # Must match above
    note: "..."
```

---

**Problem:** More than 3 articles pinned

**Cause:** Too many articles with `weight: 10`

**Fix:**
```yaml
# On oldest pinned article, reduce weight:
weight: 7  # or any value 1-9
```
