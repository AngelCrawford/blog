## What Didn't Go Well

### Test execution discipline (Angel's #1 concern)
The dev cycle frequently triggered the **full test suite repeatedly** during fix iterations rather than using targeted runs. Up to 5 full-suite re-runs per story without added signal. Significant cumulative time loss across the epic.

**Root cause:** No established cycle discipline. Long suites + "let me check everything once more" instinct + lack of muscle-memory for `--grep`, single-file invocation, or Playwright `-g`.

**Not Angel's failure to read drafts** — this is a workflow issue, addressed by action item A1.

### Spec assumptions verified false at implementation time
Recurring pattern across the epic:
- Story 1.5: claimed "`xmllint` already present in CI" — false, `git log` disproved it
- Story 1.1: claimed `.github/workflows/` empty — `daily-rebuild.yml` existed
- Story 1.1: claimed `.zed/settings.json` should be created — already existed
- Story 1.4: spec said `notification is-warning`, rendered output flipped to `message is-warning`

Story-context drafts fabricate prior-state claims. Treating them as facts cost rework.

### Mid-story refactors and AC reversals
Six documented pivots in five stories:
- Story 1.1: Husky → plain git hooks (mid-review)
- Story 1.2: Icon substitutions (`plant-line` → `flower-line`, `skull-line` → `skull-2-line`) — Remix Icon subset didn't include the spec'd glyphs
- Story 1.2: `<div class="card-footer-item">` → `<span class="growth-stage">` (DOM cleanup post-implementation)
- Story 1.2: Seedling/Budding/Log colors changed during review across multiple iterations
- Story 1.3: AC #3 (archive inclusion) and AC #7 (footer total) reversed AFTER review
- Story 1.4: `notification is-warning` → `message is-warning` post-implementation

Each individual change was justified, but the volume signals **acceptance criteria pass too easily through the draft gate**.

### Real-content collision risk
Story 1.4 added `withered_date` conditional-required validation. Production article `content/articles/movie-test/index.md` had `growth_stage: withered` without `withered_date`, breaking the production build. Backfilled as a side-fix. **Production content is a hidden test fixture** — needs auditing before build-time validation lands.

### Hugo template engine surprises
Each story hit at least one Hugo-template gotcha:
- `else with` not allowed (Story 1.5 → swapped to `else if`)
- `:date_short` returns numeric format for `de-DE` (Story 1.5 → literal German month slice)
- `string $time` coercion produces `"2026-04-15 00:00:00 +0000 UTC"` (Story 1.5 broke Story 1.4's regex)
- YAML auto-parses dates unless quoted
- `cascade.sitemap.priority` invisibly overrides site config (Story 1.5 side-fix)
- `where ... ne nil` semantics for nil values (Story 1.3)

### Bundling/CSP debugging chain (Story 1.4)
Multi-step debugging cascade:
1. JS minifier ate the leading paren of `(function(){})()` → switched to `!function(){}()`
2. CSP `script-src 'self'` blocked production-domain absolute URLs on localhost → `Permalink` → `RelPermalink` (project-wide change)
3. `#resultsWrapper` z-index 9999 invisibly intercepted tap-target tests
4. Real-content `movie-test` collision discovered at build-time

Each fix unblocked the next bug. Not a clean cycle.

### Scope renegotiation post-hoc
- Story 1.5 absorbed Story 9.6's scope (rescoped to "verification slot")
- Story 1.2 AC #1 ("top-right corner") overridden by ADR-005 (card footer)
- Story 1.2 AC #5 ("every card") doesn't match implementation (excludes `format=log`)

## Key Insights

1. **Defense-in-depth pays off.** 3 layers + CI = `growth_stage` is bulletproof. Pattern is reusable for any future enum-typed frontmatter field.
2. **Cross-story patching is healthy** as long as it's tracked in the backlog. Each patch made the codebase better; backlog discipline kept it visible.
3. **Spec drafting needs a reality-check pass.** Too many "already present" claims and ad-hoc icon/component picks. A lightweight pre-flight on each story-context prevents half the mid-story pivots.
4. **Test discipline > test count.** 40 build-smoke + 19 e2e is healthy; running them 5× per story is not.

## Action Items

### A1. Test execution discipline (HIGH PRIORITY)
- **Owner:** Dev (every story)
- **Rule:** Full suite once → read output → fix → **targeted runs only** during iteration → one final full-suite confirmation. No mid-cycle full re-runs.
- **Targeted-run primitives:** `node --test path/to/file.test.mjs`, `npx playwright test -g "test name"`, single-spec invocation.
- **Success criteria:** No Epic 2 story shows >2 full-suite runs in its dev log when fixing iteratively.
- **Persistence:** Saved to feedback memory `feedback_no_redundant_test_runs.md` (updated 2026-05-09).

### A2. Story-context reality-check pass (MEDIUM)
- **Owner:** Dev (at story start)
- **Rule:** Before implementing, verify any "already present" / "does not exist" / "is empty" claims in the story context. Treat them as questions, not facts. ~5-10 min per story.
- **Success criteria:** Zero mid-implementation surprises traced back to false story-context claims in Epic 2.
- **Trigger:** Story 2.1 sets the precedent.

### A3. Real-content pre-flight before validation rules (MEDIUM)
- **Owner:** Dev (any story adding build-time validation or global layout changes)
- **Rule:** When a story adds `errorf` validation or modifies global layout, run `hugo --environment production` against current real content BEFORE writing tests. If existing content fails, document and backfill explicitly (not as a sneaky side-fix).
- **Success criteria:** No production-content collisions discovered during e2e debugging.
- **Triggered by:** Stories 2.5 (privacy policy footer), 2.7 (cookie banner global), 3.x onward.

### Team Agreements

1. **Targeted test runs by default** during fix cycles — full suite is a checkpoint, not a habit.
2. **Spec claims are questions until verified** — story-context reality check is a 5-min insurance policy.
3. **Pre-existing content is a hidden fixture** — audit before validation rules land.
4. **Backlog is source of truth** — no backport to `epics.md`; cosmetic drift accepted.

### Documentation

No backport to `epics.md`. Per Angel's call: "vieles aus epic 1 wird später nochmal relevant" — backlog continuity over historical accuracy in epic file.
