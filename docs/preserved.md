1	# ADR: Multi-Author Schema → Single + Optional Co-Author
2	
3	**Status:** Accepted
4	**Date:** 2026-05-12
5	**Decided:** 2026-05-12
6	**Owner:** Angel Crawford
7	**Related:** [`adr-domain-migration.md`](./adr-domain-migration.md) (Identity
8	Unification), [`docs/1-planning/epics.md`](../1-planning/epics.md)
9	(Stories 9.2, 9.10, 9.13)
10	
11	---
12	
13	## Context
14	
15	The current Hugo project carries a **multi-author content model**
16	inherited from the original "Article Time" magazine concept:
17	
18	- **Taxonomy:** `config/_default/config.yaml` defines
19	  `taxonomies.author: authors`, generating per-author bio pages under
20	  `/authors/<slug>/`.
21	- **Content directory:** `content/authors/` holds two author terms:
22	  - `angel/_index.md` — Angel Crawford (real, with birthdate, socials,
23	    website, full bio).
24	  - `jdksaj/_index.md` — test fixture "HJKHJ Udsanhjs" pointing at a
25	    Bruce Willis Wikipedia URL.
26	- **Frontmatter:** articles/logs use `authors: [...]` (array of
27	  taxonomy term slugs). Across the four content files in the repo,
28	  three are single-author (`["angel"]`); the fourth
29	  (`content/articles/test/index.md`) is multi-author
30	  (`["jdksaj", "angel"]`) and is itself test content.
31	- **Templates:** `layouts/single.html:212` branches on
32	  `.Params.authors`. `layouts/_partials/_base/seo.html:111` and
33	  `footer.html:102` resolve the site-default author via
34	  `.Site.Params.author.name`.
35	- **Known drift:** Story 9.2 (Schema.org Structured Data) Pre-Spec
36	  Notes flag a *BlogPosting multi-author duplicate-key bug* in
37	  `seo.html`. Story 9.10 (Author-Box) AC4 specifies "Multiple authors:
38	  all displayed; if more than 3, collapse with '+N more' toggle" — UI
39	  scaffolding for a multi-author future that, in this project's
40	  reality, has only ever produced one test fixture.
41	
42	Separately, the [Domain & Brand Migration ADR](./adr-domain-migration.md)
43	(Accepted 2026-05-12) establishes the site as a **personal,
44	single-author digital garden** under `angel-crawford.de`. Story 9.13
45	introduces `params.identity` (`name`, `photo`, `note`, `url`) as the
46	canonical h-card identity source.
47	
48	This leaves the project carrying two parallel author identity
49	abstractions:
50	
51	1. **Site-owner identity** — `params.author.name`,
52	   `params.identity.*`, footer copyright, JSON-LD `author` field.
53	2. **Per-article author taxonomy** — `authors: [...]` frontmatter,
54	   `content/authors/<slug>/`, taxonomy-driven Author-Box.
55	
56	The IndieWeb principle "one h-card per person, linked between sites"
57	makes the internal taxonomy redundant for the realistic case (one
58	site, one main author, occasional co-authors who have their own
59	sites). Mainstream feed readers do **not** consume h-entry-internal
60	author taxonomies, so the abstraction provides no downstream value.
61	
62	---
63	
64	## Decision
65	
66	Replace the multi-author taxonomy model with a **single-author default
67	plus optional co-authors** model:
68	
69	### Frontmatter schema
70	
71	```yaml
72	# Optional. Defaults to params.identity.name.
73	author: "Some Name"
74	
75	# Optional. Array of co-author objects.
76	coauthors:
77	  - name: "Co-Author Name"
78	    url: "https://co-author-site.example"
79	```
80	
81	- `author:` field is **optional**; absence resolves to
82	  `params.identity.name` (the site owner).
83	- `coauthors:` field is **optional**; absence renders no co-author
84	  block. Each entry is an **object** with `name` (required) and `url`
85	  (optional). The object form is forward-compatible: future fields
86	  like `photo`, `bio`, or `mastodon` can be added without a schema
87	  break.
88	
89	### Author taxonomy removed
90	
91	- `taxonomies.author: authors` removed from
92	  `config/_default/config.yaml`.
93	- `content/authors/` directory removed (all three files:
94	  `_index.md`, `angel/_index.md`, `jdksaj/_index.md`).
95	- No more auto-generated `/authors/<slug>/` pages. The site owner's
96	  bio lives via `params.identity` (and, if longer-form, on the home
97	  page itself or a dedicated `/about/` page).
98	
99	### `params.author` → `params.identity` consolidation
100	
101	- `params.author.*` removed.
102	- `params.identity` becomes the canonical single source for
103	  site-owner identity. Story 9.13 introduces the minimum shape
104	  (`name`, `photo`, `note`, `url`); this ADR extends it for the
105	  footer/JSON-LD use case (see § What changes below).
106	- `params.default_author_name` fallback chain in
107	  `footer.html` line 102 collapses to a single
108	  `params.identity.name` reference.
109	
110	### Co-author rendering convention (IndieWeb-aligned)
111

## Acceptance Criteria

### 1. Security — `javascript:` / `data:` URI guard for webmention author + source links

`layouts/_partials/widgets/webmention-group.html` (around lines 20–34) emits `<a href="{{ .author_url }}">` and `<a href="{{ .url }}">` without scheme filtering. Hugo's auto-escape covers HTML injection but **not** protocol injection — a webmention.io payload with `author_url: "javascript:alert(1)"` would render as an executable link.

**Why this matters more now:** Once Story 2.8 (Bridgy.fed) lands, any Fediverse account can craft a webmention payload via Mastodon → Bridgy → webmention.io. Attack surface grows from "IndieWeb-blog subset" to "anyone with a Mastodon account."

**Fix:** allowlist filter — emit `href` only if URL scheme is `http://`, `https://`, or `mailto:`; otherwise fall through to the plain-text/`<span>` branch already in place. Add a build-smoke assertion (fixture entry with `author_url: "javascript:alert(1)"` must render as `<span>`, not `<a href>`).

### 2. Robustness — `hearts.js` storageKey baseURL-independence

`assets/js/hearts.js` (around line 25) builds the localStorage key from `data-article`, rendered as `$page.RelPermalink`. If `baseURL` changes (subpath deploy, custom-domain migration, prod→staging mirror), `RelPermalink` shifts and every existing `hearted-…` entry silently orphans → users lose visible hearted-state.

**Why this matters now:** Stories 9.14 + 9.15 (domain migration `article-time.de` → `angel-crawford.de`) are queued. Without this fix, every user's hearted-state evaporates the day we cut over.

**Fix:** stabilise the key — use `window.location.pathname` directly (browser-side resolved, no baseURL prefix), or strip a known prefix from `data-article` before use. Add a code comment explaining the design intent so a future maintainer doesn't "fix" it back to the simpler raw form.

### 3. Test quality — adversarial XSS fixture for webmention build-smoke test

`tests/build/build-smoke.test.mjs` (around line 1661, Story 2.4 AC #8 XSS auto-escape test) uses clean fixture data — no HTML payloads. The "Hugo auto-escape is active" assertion is technically unverified.

## Was die About-Page dann ist (deine Frage)

**Mehr-Content, ja** — aber legitimer Mehr-Content, kein doppelter Boilerplate. Die About-Page ist nicht mehr „IndieWeb-Pflicht", sondern Long-Form-Profil:
- Größerer Avatar, persönlichkeitsstarke Darstellung
- Birthdate / Alter (dynamisch)
- Strukturierte Bullets
- Free-text Long-Bio (kannst du nach Lust befüllen — Gummibärchen-Text aus dem alten `_index.md` z.B.)
- Spätere Erweiterungen: Spotify-Embed, Werdegang, Now-Page, Kontakt

Der Footer linkt zur About-Page als „mehr Details über die Person hinter dem Footer". Das ist **die kanonische IndieWeb-Page-Hierarchie**: kleine ständige Identitäts-Präsenz + große dedizierte Persönlichkeits-Page.
